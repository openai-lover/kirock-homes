# Live Dialogue — Design

**Author:** Kiro (2026-11-05).

---

## Module structure

Single file: `src/lib/chat/performance.ts`.

No classes.  Two exported functions and two exported types.  All helpers are unexported
module-level functions.  No mutable module-level state.

---

## Separation of concerns

```
┌────────────────────────────────────────────────────────────────────────┐
│  Official evidence layer (Codex-owned)                                 │
│  PublicStatement text · authored case copy · confession catalogue      │
│  Always rendered by code; never touches Performance                    │
└────────────────────────────────────────────────────────────────────────┘
          ↕  (UI composes both into the chat stream)
┌────────────────────────────────────────────────────────────────────────┐
│  Performance layer (Kiro-owned)                                        │
│  Non-evidentiary character reactions generated by AI                  │
│  Validated by validatePerformance — structural check only             │
│  Optionally passed through performanceReviewPassed — probabilistic     │
└────────────────────────────────────────────────────────────────────────┘
```

A Performance line's `quoteIds` may reference public statement IDs so the UI can render
an inline citation badge, but the statement text itself is always fetched and rendered
from the official evidence layer.

## `validatePerformance`

```ts
function validatePerformance(
  raw: unknown,
  input: {
    target: 'auto' | 'kirock' | 's0' | 's1' | 's2';
    statementIds: readonly string[];
    suspectIds: readonly string[];
  },
): Performance
```

### Validation pipeline

1. **Plain-object guard** — `raw` must be a non-null, non-array object with `Object.prototype`
   or `null` prototype.  Throws `TypeError` otherwise.

2. **Top-level forbidden-key scan** — iterate `Object.keys(raw)`:
   - Exact forbidden names (case-insensitive): `answer`, `culprit`, `culpritid`, `confession`,
     `factinverted`, `roleassignment`, `proofsteps`, `proof`, `solution`, `verdict`, `guilty`.
   - Forbidden substrings (case-insensitive): `private`, `secret`.
   - Any key not in `{ lines }` is also rejected.

3. **`lines` presence and type** — `lines` must exist and be an array.

4. **Line count** — 1 or 2 entries; 0 or 3+ throws.

5. **Per-line validation** (loop with shared `seenSpeakers` set):
   a. Plain-object check.
   b. Line-level forbidden-key scan (same rules as step 2).
   c. Allowed-key check: exactly `{ speakerId, text, quoteIds }`.
   d. Required-field presence for each of the three keys.
   e. `speakerId` type + enum + `suspectIds` membership.
   f. Duplicate-speaker check via `seenSpeakers`.
   g. `text` type, trim, length (1–240), code-fence check (before control-char check),
      HTML check, URL check, control-character check, confession-pattern check.
   h. `quoteIds` array check, length (0–2), per-entry type + `statementIds` membership +
      duplicate check.

6. **First-speaker / target enforcement** — when `input.target !== 'auto'`,
   `lines[0].speakerId` must equal `input.target`.

7. **Return** — `{ lines: validatedLines }`.

### Key ordering note

Code fences are checked before control characters.  A multi-line code-fence string (```` ``` \n … ``` ````)
contains a newline (U+000A), a control character.  Checking fences first produces the more
descriptive `"contains a code fence"` error.

### Error messages

All `TypeError` messages are prefixed with `[validatePerformance]` and identify the offending
field, index, or condition.

## `performanceReviewPassed`

```ts
function performanceReviewPassed(raw: unknown): boolean
```

### Algorithm

1. `isPlainObject(raw)` → `false` if not.
2. `Object.keys(raw).length === 4` → `false` if not.
3. Check each expected key/value pair with strict `===`:
   - `raw['approved'] === true`
   - `raw['newFact'] === false`
   - `raw['solutionLeak'] === false`
   - `raw['statementRewrite'] === false`
4. Verify no unexpected keys by checking every key is in the expected set.
5. Return `true` only if all checks passed.

This does not catch semantic errors in the reviewed Performance; it only confirms the reviewer
returned the expected approval shape.

## `isPlainObject` (private helper)

```ts
function isPlainObject(v: unknown): v is Record<string, unknown>
```

Returns `true` for plain `{}` literals and `Object.create(null)` objects.  Returns `false` for
`null`, arrays, class instances, and any object whose prototype is neither `Object.prototype`
nor `null`.

---

## `rejectForbiddenKeys` (private helper)

```ts
function rejectForbiddenKeys(obj: Record<string, unknown>, context: string): void
```

Iterates `Object.keys(obj)`.  For each key, lowercases and checks against `FORBIDDEN_EXACT`
(Set) and `FORBIDDEN_SUBSTRINGS` (array).  Throws `TypeError` on first match, including
`context` in the message.

---

## `findDirectConfessionPattern` (private helper)

```ts
function findDirectConfessionPattern(text: string): string | undefined
```

NFKC-normalises `text`, then tests against each pattern in `CONFESSION_PATTERNS_EN` and
`CONFESSION_PATTERNS_KO`.  Returns the matching pattern's `source` string, or `undefined`
if none matched.

**Defense-in-depth only.**  This cannot prevent indirect admissions or paraphrases.

## Isolation guarantee

Neither exported function imports from `solver`, `generator`, `render`, `server-only`,
`share-store`, any AI module, or any module that touches private case-resolution fields.
The private solution is never an argument.
