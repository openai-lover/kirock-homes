# Live Dialogue — Requirements

**Author:** Kiro (2026-11-05).
**Scope:** `src/lib/chat/performance.ts`, `tests/performance.test.ts`, and this spec directory only.

---

## Background

The group-chat UI renders two kinds of character output per turn:

1. **Official evidence** — public statements, authored case copy, templated confession — always
   rendered by code from static catalogues.  This module has no part in that path.

2. **Performance reactions** — short non-evidentiary emotional colour, banter, or deflection —
   optionally generated by an AI model to give characters a living voice.  This module owns the
   contract for that second kind.

A Performance is a validated, bounded payload.  Its text is display-ready reaction prose that
accompanies a turn; it never replaces, paraphrases, or extends the official evidence.

## Functional requirements

### FR-1 Exported public surface

The module exports exactly these named items:

| Name | Kind |
|---|---|
| `PerformanceLine` | type |
| `Performance` | type |
| `validatePerformance` | function |
| `performanceReviewPassed` | function |

No additional runtime exports.

### FR-2 Type shapes

```ts
type PerformanceLine = {
  speakerId: 'kirock' | 's0' | 's1' | 's2';
  text: string;
  quoteIds: string[];
};

type Performance = {
  lines: PerformanceLine[];
};
```

### FR-3 `validatePerformance(raw, input)` — acceptance rules

`input` shape:

```ts
{
  target: 'auto' | 'kirock' | 's0' | 's1' | 's2';
  statementIds: readonly string[];
  suspectIds: readonly string[];
}
```

Structural checks (throws `TypeError` on violation):

- `raw` must be a plain object (not null, array, primitive, or class instance).
- `Performance` may contain only the key `lines`; any other key is rejected.
  - Keys matching (case-insensitive) any forbidden name are rejected:
    `answer`, `culprit`, `culpritId`, `confession`, `factInverted`, `roleAssignment`,
    `proofSteps`, `proof`, `solution`, `verdict`, `guilty`.
  - Keys containing the substrings `private` or `secret` (case-insensitive) are rejected.
- `lines` must be present, must be an array, and must contain exactly 1 or 2 entries.
- Each `PerformanceLine` must be a plain object with exactly the keys `speakerId`, `text`,
  `quoteIds`; forbidden-key rules apply inside each line as well.
- `speakerId` must be one of `'kirock'|'s0'|'s1'|'s2'`, and if it is a suspect ID it must appear
  in `input.suspectIds`.
- No `speakerId` value may be repeated across lines in the same Performance.
- When `input.target` is not `'auto'`, the first line's `speakerId` must equal `input.target`.
- `text` must be a non-empty string of 1–240 characters after trimming.
- `text` must not contain:
  - Control characters (U+0000–U+001F, U+007F–U+009F).
  - HTML tags.
  - HTTP/HTTPS/FTP URLs.
  - Markdown code fences (` ``` `).
- `text` must not match any direct-confession/verdict pattern (see FR-5).
- `quoteIds` must be an array of 0–2 string entries, each present in `input.statementIds`, with
  no duplicates.

Returns a typed `Performance` when all checks pass.

### FR-4 `performanceReviewPassed(raw)` — review acceptance rules

Returns `true` if and only if `raw` is the exact object:

```ts
{ approved: true, newFact: false, solutionLeak: false, statementRewrite: false }
```

All four keys must be present with those exact literal values; no extra keys are permitted.
Returns `false` for any other value, including null, arrays, wrong types, partial matches, and
extra keys.

### FR-5 Conservative confession/verdict pattern guard (defense-in-depth)

A conservative set of regex patterns is applied to `text` (after NFKC normalisation) to catch
obvious direct-confession or verdict-disclosure phrases.  English and Korean patterns are included.

**This is defense-in-depth only.**  It catches obvious literal phrases and must not be claimed
as semantic prevention of solution leaks.  See NFR-2 for the documentation obligation.

English examples caught: "I did it", "I am the culprit", "I am guilty", "It was me",
"The culprit is", "The answer is", "I confess".

Korean examples caught: 내가 했어, 내가 범인, 제가 했어요, 범인은, 정답은, 내가 한 거야, 내가 저질렀어.

### FR-6 Import restrictions

- Must not import `solver`, `generator`, `render`, `server-only`, `share-store`, AI modules, or
  any module that exposes private case-resolution fields.
- The private solution (culpritId, factInverted, roleAssignment, proofSteps, confession) must not
  be passed as an argument or be importable from this module.
- May only import from Node.js builtins or type-only from `../game/types`.

## Non-functional requirements

- NFR-1 No runtime dependencies beyond Node.js builtins.
- NFR-2 Code and documentation must clearly distinguish structural validation from probabilistic
  semantic review.  Claims of absolute prevention of semantic leaks are prohibited.
- NFR-3 Pure functions — no module-level mutable state.
- NFR-4 TypeScript strict mode compliant.
