첨부한 KIROWEEN_2026_PLAN.md를 읽고 Kiroween 2026 출품작 “범인은 내 방에 / Room of Suspects”의 핵심 기능을 실제로 개발해줘.

핵심 경험
사용자 사진 위의 물건 세 개가 SVG 눈과 입으로 살아난다. 짧은 공식 증언 세 개를 비교하고 범인 한 명을 한 번 지목한다. 첫 각성 10초와 자백의 타이밍이 중요하다.

먼저 할 일
저장소와 기존 변경을 확인하고 Kiro Specs를 사용해 다음 네 기능의 requirements.md, design.md, tasks.md를 만들어줘:
- case-engine
- photo-casting
- awakening-scene
- share-case
product.md, tech.md, structure.md 등 steering에는 이 게임의 목적·스택·규칙을 넣어줘.
현재 설치 버전에 맞는 hook 형식을 공식 문서에서 확인하고, 추리 코드 변경 시 논리 검사를 실행하는 hook을 실제로 설정·실행해줘.
파일 생성만으로 끝내지 말고 아래 핵심 구현을 진행해줘.

추리 엔진
범인 3명 × 이진 사건 상태 2개로 여섯 세계를 평가해줘.
기본 템플릿:
- A의 공식 증언: fact=true
- B의 공식 증언: fact=false
- C의 공식 증언: culprit=A
A/B/C는 실제 물건과 다르며 무작위로 대응한다.
세계마다 모든 증언에 대해 evaluate(claim, world) === (speakerId !== culpritId)가 성립하는지 검사한다.
정답 세계가 정확히 하나여야 한다.
어떤 증언 하나를 빼도 범인 후보가 최소 두 명이 남아야 한다.
역할 배정, 사건 상태 반전, 표시 순서에 대해 전수 검증한다.
검증기가 잘못된 사건도 실제로 거부하는지 확인한다.
문장과 해설은 코드에서 렌더링하고 AI가 의미를 바꾸지 못하게 해줘.

구현 순서
1. 순수 TypeScript 엔진, 문장 렌더러, 해설, 검증.
2. 샘플 사진 한 장과 SVG 얼굴 세 개.
3. 각성→증언 수집→최종 지목→정답·오답→해설의 전체 흐름.
4. 이후 내 사진 업로드·수동 캐스팅과 얼굴 보정.
5. 별도 작업으로 공유와 비전을 연결한다.

기술
Next.js + TypeScript, CSS와 SVG를 기본으로 한다.
처음에는 외부 API 키 없이 실행되어야 한다.
공식 증언, 정답, 해설은 AI에 맡기지 않는다.
실제 물건 사진을 새 캐릭터 이미지로 대체하지 않는다.
지목 전 애니메이션은 범인과 독립적으로 정한다.
기본 라이브러리 대사를 쓰고 자유 대화·TTS·3D·랭킹·로그인은 제외한다.
한국어와 영어를 같은 논리 데이터에서 렌더링한다.

개발 기록
docs/kiro-usage.md에 실제 수행한 명세 작성·구현·오류 수정·hook 실행·검증을 기록해줘.
문제, 사용 기능, 실제 변경, 검사 결과, 관련 커밋을 연결해줘.
사용하지 않은 Kiro 기능, 실행하지 않은 테스트, 존재하지 않는 성과를 기록하지 마.
실험용 오류를 심어 검증했다면 실험이라는 사실을 밝혀줘.
Codex에서 이미 작성된 작업은 Kiro 작성으로 바꾸지 말고 출처를 유지해줘.

첫 완료 기준
샘플 사진에서 세 물건이 깨어나고, 세 증언을 들을 수 있으며, 한 번 지목해 올바른 정답 또는 오답 반응과 해설을 볼 수 있어야 한다.
이를 실제 브라우저에서 확인하고 관련 논리 테스트·타입 검사·빌드를 실행해줘.

추가 구현 계약
- 사건의 이진 사실 대상은 논리 역할 배정과 독립시킨다. 화자가 바뀌어도 같은 대상의 상태를 비교하고, '나는'은 화자와 대상이 같을 때만 쓴다.
- 공유 서버는 승인된 템플릿·사건 버전과 역할 매핑에서 공식 문장·정답·해설을 재구성한다. 클라이언트 문장이나 factLabels를 신뢰하지 않는다.
- 로컬 판은 브라우저에서 판정하고 공유판은 서버에서 판정한다. 공개 응답의 정답 미노출은 공유판에 적용한다.
- 공유 시 한영 내용을 고정하고 locale 요청에 따라 같은 사건의 해당 언어를 반환한다.
- 크롭은 캐스팅 전에만 한다. 공유 직전 사진을 바꾸려면 새 캐스팅부터 시작한다.
