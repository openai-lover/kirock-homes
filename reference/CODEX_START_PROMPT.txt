첨부한 KIROWEEN_2026_PLAN.md를 제품 요구사항과 개발 명세로 사용해 “범인은 내 방에 / Room of Suspects”를 단계적으로 구현해줘. 파일이 프로젝트에 있으면 먼저 docs/KIROWEEN_2026_PLAN.md 또는 실제 첨부 경로를 읽어. 없는 문서를 읽었다고 가정하지 마.

목표
사용자 사진 속 물건 세 개에 SVG 눈·입을 붙이고, 약 3분 동안 세 공식 증언을 비교해 범인 한 명을 한 번 지목하는 코미디 추리 웹게임이다. 첫 각성과 자백의 완성도가 가장 중요하다.

공모전과 도구 사용
이 프로젝트는 Kiroween 2026 출품용이다. Kiro를 실제 개발에 사용해야 하며, Codex가 .kiro 파일만 만든 것을 Kiro 활용으로 기록하면 안 된다.
기존 Kiro 명세·변경·검사 기록을 먼저 확인하고 사실과 초안을 구분해라.
Kiro에서는 case-engine과 awakening-scene의 핵심 개발을 수행하는 계획이다. 기존 Kiro 작업을 존중하고 동일 파일을 동시에 수정하지 마.
Kiro CLI가 실제로 설치·인증되어 있고 사용할 수 있다면 현재 공식 문서를 확인해 활용할 수 있다. 실행하지 않은 명령·테스트·증빙은 만들지 마.
Kiro를 실행할 수 없으면 구체적인 입력·예상 파일·인수 조건을 KIRO_HANDOFF.md에 남기고, 독립적인 구현과 검토는 계속해라. 실제 Kiro 사용이라는 대회 요건이 아직 남아 있음을 명시해라.

기술 기본안
Next.js + TypeScript 단일 프로젝트, CSS와 SVG 얼굴, 순수 TypeScript 추리 엔진.
처음에는 외부 계정·API 키 없이 동작하는 샘플 사진, 수동 캐스팅, 검수 대사, MockProvider.
공유 단계에서 Supabase Postgres와 private Storage를 연결하는 구조. 실제 제공자 설정이 없으면 연결된 척하지 말고 로컬 개발용 어댑터와 필요한 환경변수를 분명히 제공.
현재 호환되는 안정 버전과 공식 문서를 확인하고 잠금 파일을 유지.
비전 모델은 서버 전용 어댑터에 격리하고 API 키를 클라이언트에 노출하지 마.

변경 불가능한 제품 규칙
1. “세 공식 증언 중 범인의 증언 하나만 거짓이고 나머지 둘은 참”이다.
2. 범인 3명 × 이진 사건 상태 2개, 여섯 세계를 모두 검사한다.
3. 기본 템플릿은 역할 A: fact=true, B: fact=false, C: culprit=A. 역할은 실제 물건에 무작위 배정한다.
4. 유효한 세계가 정확히 하나이며, 증언 하나를 제외하면 범인 후보가 두 명 이상이어야 한다.
5. 공식 증언과 해설은 코드가 렌더링한다. AI가 생성·의역하지 않는다.
6. AI는 후보 물건·성격·검수 대사 선택만 돕는다. 실패해도 수동 모드로 완주한다.
7. 지목 이전의 표정이나 애니메이션은 범인 여부를 누설하지 않는다.
8. 사진은 원형을 유지하고 얼굴·조명·짧은 말풍선만 얹는다.
9. 같은 공유 링크는 같은 사진·대사·증언·정답을 유지한다.
10. 공유 공개 응답에는 정답·해설·자백·내부 seed·비공개 역할 mapping을 포함하지 않는다.
11. 개인 사진은 공유 확인 전 저장하지 않는다. 선택적 AI 분석의 이미지 전송은 별도로 안내한다.
12. 7일 만료·삭제는 실제 구현과 검증 뒤에만 사용자에게 약속한다.
13. 샘플 데모는 키 없이 작동하고 심사 기간에 만료되지 않게 별도 운영한다.
14. 한국어·영어, 자막, 음소거, 동작 줄이기, 모바일·키보드 조작을 제공한다.

작업 방식
처음에 저장소, AGENTS.md, 기존 변경, 실행 환경을 확인해라. 작업을 나누되 같은 파일은 동시에 수정하지 마.
이미 구현된 부분은 먼저 확인하고 재작성하지 마.
불필요한 프레임워크·계정·기능을 추가하지 마.
출처와 사용 권한이 분명한 샘플 사진을 사용해라. 실제 사진이 없으면 임시 자산임을 명확히 하고 최종 필요 자료에 기록해라.
상태별 오류·빈 화면·다시 시도·AI 시간 초과를 함께 구현해라.
단계마다 실제 실행, 의미 있는 검사, 화면 확인을 하고 결과를 docs/validation-results.md에 기록해라.
완료하지 않은 항목을 완료로 표시하거나 테스트가 통과했다고 추정하지 마.
권한·API 키가 필요한 외부 작업만 구체적으로 설명하고, 그와 독립적인 로컬 작업을 계속해라.

단계
M0: 기획 읽기, 기존 구현 확인, 작업 분해, Kiro 역할과 실제 증빙 구분.
M1: 샘플 사진 한 장에서 각성→세 증언→한 번 지목→정답·오답→해설까지 완성.
M2: 사진 업로드·방향 보정·세 점 캐스팅·얼굴 크기와 위치 보정, 모바일 대응.
M3: 선택적 비전 어댑터와 시간 초과·잘못된 출력 대체.
M4: 동일 사건 공유, 서버 판정, 공개 DTO, 소유권·삭제·만료·중복 요청 처리.
M5: 접근성·한영·실기기 확인, 사용자 테스트 반영, README·배포·제출 안내 정리.

우선 M1을 실제로 작동하게 만들어라. 그 뒤 완료 기준을 만족하는 순서로 계속 진행해라. 외부 제공자 연결이 막히면 해당 의존성을 정확히 기록하고 독립 작업은 마쳐라.

필수 검사
- 승인된 추리의 모든 역할·상태·표시 순서 변형과 증언 필요성.
- 잘못된 템플릿을 검증기가 거부하는지.
- 해설과 실제 해의 일치.
- 가로·세로·회전 사진 및 모바일 좌표.
- AI timeout·키 없음·잘못된 JSON에도 완주.
- 공유 응답의 정답 미노출, 동일 사건, 만료·삭제·무권한 접근.
- 최종 지목의 중복 요청, 새로고침 뒤 결과 유지.
- 샘플 정답·오답과 키보드·동작 줄이기 경로.
- 타입 검사·관련 테스트·실제 빌드.

작업 후에는 구현한 기능, 실제 실행한 검사, 현재 실행 방법, 외부 설정 때문에 남은 일, 실제 Kiro 사용 증빙 상태를 간결하게 알려줘. 기획만 다시 설명하고 끝내지 마.

추가 구현 계약
- 사건의 이진 사실 대상은 논리 역할 배정과 독립시킨다. 화자가 바뀌어도 같은 대상의 상태를 비교하고, '나는'은 화자와 대상이 같을 때만 쓴다.
- 공유 서버는 승인된 템플릿·사건 버전과 역할 매핑에서 공식 문장·정답·해설을 재구성한다. 클라이언트 문장이나 factLabels를 신뢰하지 않는다.
- 로컬 판은 브라우저에서 판정하고 공유판은 서버에서 판정한다. 공개 응답의 정답 미노출은 공유판에 적용한다.
- 공유 시 한영 내용을 고정하고 locale 요청에 따라 같은 사건의 해당 언어를 반환한다.
- 크롭은 캐스팅 전에만 한다. 공유 직전 사진을 바꾸려면 새 캐스팅부터 시작한다.
